# qmd-Spike (2026-10-03)

## Ergebnis

- GPU-Backend: **CPU** (8 Kerne). CUDA wird nicht genutzt: `qmd doctor` meldet „NVIDIA driver libraries are visible, but CUDA user-space libraries are missing from loader paths (CUDA runtime, cuBLAS, cuBLASLt)“. Vulkan: `NoBinaryFoundError`, Fallback auf CPU.
- Benötigte Umgebungsvariablen: keine (optional `QMD_FORCE_CPU=1`, um die CPU-Warnung zu unterdrücken).
- qmd-Version: 2.8.3 (facd35e), global per `npm install -g @tobilu/qmd` (npm-Prefix unter nvm, kein sudo nötig).
- Zeitzone WSL: Europe/Berlin (passt für Archivnamen und LOG.md).

## GPU nachrüsten (optional, Entscheidung des Nutzers)

Für CUDA auf der RTX 5070 Ti (Blackwell) fehlen nur die CUDA-12-Laufzeitbibliotheken (≥ 12.8: `libcudart`, `libcublas`, `libcublasLt`). Varianten:
1. NVIDIA-Repo für WSL-Ubuntu einbinden und `sudo apt install cuda-runtime-12-8 libcublas-12-8` (bzw. neuer) installieren; `qmd doctor` erneut ausführen.
2. Ohne sudo: Bibliotheken als pip-Wheels (`nvidia-cuda-runtime-cu12`, `nvidia-cublas-cu12`) in ein venv installieren und deren `lib`-Verzeichnisse in `LD_LIBRARY_PATH` aufnehmen.

Funktional ändert sich nichts; nur `embed`/`query` werden schneller.

## Konfiguration

- Konfigurationsdatei: `~/.config/qmd/index.yml`; Index: `~/.cache/qmd/index.sqlite` (Linux-Dateisystem).
- Embedding-Modell dauerhaft gesetzt über: `models.embed` in `index.yml`. **Wichtig:** `qmd collection add` schreibt einen `models:`-Block mit den Standardmodellen in `index.yml`; dieser hat Vorrang vor `QMD_EMBED_MODEL`. Die Umgebungsvariable allein wirkt deshalb nicht.
- Wert: `embed: hf:Qwen/Qwen3-Embedding-0.6B-GGUF/Qwen3-Embedding-0.6B-Q8_0.gguf`; nach Modellwechsel `qmd embed -f`.

## Antwortzeiten (CPU, CLI-Aufruf inkl. Modell-Laden)

| Befehl | Zeit |
|---|---|
| `qmd search "Ingress TLS"` | 0,15 s |
| `qmd query "wann sollte ich nach Norwegen fahren"` | 4,4 s |
| `qmd query "wie trainiere ich für einen Lauf"` | 4,5 s |
| `qmd embed -f` (3 Dokumente, inkl. Download Qwen3) | 57 s |

Über den MCP-Server bleiben die Modelle geladen; `query` ist dort schneller als per CLI.

## Qualität

- Deutsche Anfragen: Top-Treffer korrekt (`urlaub.md` für Norwegen, `laufen.md` für Training).

## Einrichtung

```bash
qmd collection add /mnt/f/second-brain/wiki --name wiki --mask "*/*.md"
qmd collection add /mnt/f/second-brain/archive --name archive --mask "**/*.md"
qmd context add qmd://wiki "Verdichtete, aktuelle Wissenseinträge (Deutsch), gegliedert nach Kategorien in Unterordnern. Primäre Quelle für Antworten."
qmd context add qmd://archive "Originalnotizen (Deutsch), unverdichtet und unverändert archiviert; können durch das Wiki überholt sein."
qmd update && qmd embed
qmd cleanup   # verwaiste Vektoren aus dem Spike entfernt
```

- Embedding-Modell: `models.embed` in `~/.config/qmd/index.yml` = Qwen3-Embedding-0.6B (siehe oben).
- Maske `*/*.md` geprüft: `wiki/CLAUDE.md` wird nicht indexiert (0 Dokumente trotz vorhandener Datei).
- MCP-Anbindung: `claude plugin install qmd@qmd` scheitert (Marketplace `qmd` nicht eingerichtet). Stattdessen projektlokale `.mcp.json` mit `qmd mcp` (stdio). Probe per JSON-RPC: Tools `query`, `get`, `multi_get`, `status` vorhanden. Claude Code fragt beim nächsten Start im Repo nach der Freigabe des Projekt-MCP-Servers; danach mit `/mcp` prüfen.
